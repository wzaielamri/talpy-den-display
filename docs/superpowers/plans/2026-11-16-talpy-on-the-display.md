# Talpy on the display Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One animated Talpy, made from Talpy Den's own drawing code, in a new banner at the top of the jobs card, on the alert screen, and asleep (still) on the clock face, without slowing the board.

**Architecture:** A tool (node + rsvg-convert + Python/Pillow) plays Talpy Den's clips with a seeded random, rasterises every frame, compresses it with a small run-length codec and writes one generated C file (frames + clip/mood tables). On the board, a pure-C player picks clips and frames by time, a pure-C decoder unpacks the current frame into a RAM buffer, and a small LVGL widget shows it as an RGB565A8 `lv_image`.

**Tech Stack:** C (ESP32-S3, LVGL 9.1, PlatformIO/pioarduino), host gcc for native tests, node 24 (ES modules, no npm packages), rsvg-convert, Python 3 + Pillow.

**Spec:** `docs/superpowers/specs/2026-11-16-talpy-on-the-display-design.md`

## Global Constraints

- `pio run` must build with nothing new installed: the generated `src/ui/talpy_data.c` is committed.
- Talpy is drawn only by Talpy Den's code (`<talpy-den>/package/contents/ui/talpy/`); weights and pauses come from its `MOODS` (`actions.mjs`), not retyped.
- Clips: `needs` → alert, sign, wave; `working` → typing, thinking, read; `done` → sleep, nap; `loading` → lookaround; reaction → finished. Weights: `MOODS[m].calm` (loading: `MOODS.loading.pool`). Pauses: `MOODS[m].pause`.
- Frame step 100 ms; at most about 10 pictures a second on the board.
- One scale everywhere: 1.3 px per box unit. Every frame of the player shares one canvas (global bounding box of all clips), height ≤ 112 px (the banner is 116 with a 2 px border). The tool fails otherwise.
- Pixel format RGB565A8: `w*h` RGB565 little-endian, then `w*h` alpha bytes (LVGL 9.1: alpha stride = stride / 2, stride = `w*2`).
- Compressed frames total ≤ 2,000,000 bytes; the tool fails above. App partition stays 4 MB.
- Repeatable: the same Talpy Den checkout gives a byte-identical `talpy_data.c`.
- Decode buffers come from `heap_caps_malloc` (internal RAM first, else PSRAM), never `lv_malloc` (LVGL's pool is 64 KB).
- Nothing on the clock face moves: its Talpy is one still picture, shifted with the face.
- Colours from `include/theme.h`; flat fills only (no gradients, shadows, opacity layers).
- Talpy Den fx colour (z's, notes): `#8C96A3`; its text colour: `#E9EDF2`.
- Commit messages: no Claude/Anthropic attribution lines.

## Review Focus

- Board left frozen for a long time (shade, clock face for hours), then shown again: Talpy resumes at once with one step, no burst of catch-up steps. → Task 3 `test_long_freeze_advances_one_step`.
- `millis()` wrapping past 2^32 (after ~49.7 days up, which this 24/7 board reaches): the player keeps animating. → Task 3 `test_millis_wrap`.
- A corrupt or truncated frame stream must not write past the decode buffer. → Task 1 `test_truncated_stream_fails`, `test_overlong_run_fails`.
- Moods changing while a reaction plays (a chat starts waiting during the confetti): the reaction stops and Talpy shows the new mood. → Task 3 `test_mood_change_cancels_reaction`.
- Counts of 0 and plurals in the headline ("1 chat needs you" vs "2 chats need you", "All quiet" with done = 0). → Task 5 `test_headline_*`.

## The frame codec (fixed here: the encoder and the decoder must agree)

A frame is `w*h` pixels, row-major, each `(rgb565, alpha)`. A transparent pixel is `rgb565 = 0, alpha = 0`. The stream is a sequence of ops; each op starts with one byte `op`:

| `op` | Meaning | Bytes after `op` |
|---|---|---|
| `0x00..0x7F` | `op + 1` transparent pixels (1..128) | none |
| `0x80..0xBF` | `op - 0x80 + 1` copies (1..64) of one pixel | 3: rgb565 low, rgb565 high, alpha |
| `0xC0..0xFF` | `op - 0xC0 + 1` literal pixels (1..64) | 3 per pixel, as above |

Any pixel with alpha 0 is encoded as transparent (its RGB is dropped). The encoder uses a repeat op for 2 or more equal pixels in a row, else literals. Checksum of a frame: FNV-1a 32-bit over its decoded RGB565A8 bytes (RGB plane then alpha plane), offset basis `0x811C9DC5`, prime `0x01000193`.

```c
typedef enum { TALPY_LOADING, TALPY_NEEDS, TALPY_WORKING, TALPY_DONE, TALPY_MOODS } talpy_mood_t;

typedef struct { uint32_t offset, size; uint16_t w, h; uint32_t check; } talpy_frame_t; // into data; check: FNV-1a of the decoded frame
typedef struct { uint16_t frame; uint16_t ms; } talpy_step_t;                          // show frame for ms
typedef struct { uint16_t first_step, steps; } talpy_clip_t;                            // steps[first_step .. +steps)
typedef struct { uint16_t clip; uint16_t weight; } talpy_pick_t;                        // weight: Talpy Den's weight × 10
typedef struct {
    uint16_t rest_clip;                  // looped during pauses
    uint16_t first_pick, picks;          // picks[first_pick .. +picks)

typedef struct {
    const uint8_t *data;                 // all compressed frames
    uint32_t data_size;
    uint16_t w, h;                       // the player's canvas: every frame a clip or rest step names has this size
    const talpy_frame_t *frames; uint16_t frame_count;
    const talpy_step_t *steps;   uint16_t step_count;
    const talpy_clip_t *clips;   uint16_t clip_count;
    const talpy_pick_t *picks;   uint16_t pick_count;

    uint16_t sleep_still;                // a frame (cropped to itself) for the clock face
} talpy_set_t;

extern const talpy_set_t TALPY_SET;
```

### Task 3: The player

**Files:**
- Create: `src/ui/talpy_player.h`, `src/ui/talpy_player.c`, `test/native/test_player.c`; Modify: `test/native/run.sh`

**Interfaces:**
- Consumes: `talpy_set.h` types (Task 2). Tests use a small hand-made `talpy_set_t` (no frame data needed).
- Produces:

```c
typedef struct {
    const talpy_set_t *set;
    uint32_t rng;            // xorshift32 state, never 0
    talpy_mood_t mood;
    int16_t clip;            // playing clip, or -1: resting (the mood's rest clip loops)
    bool reacting;           // the playing clip is the reaction
    uint16_t step;           // step within the playing clip or the rest clip
    uint32_t step_due;       // when the current step ends
    uint32_t pause_due;      // while resting: when the next clip starts
} talpy_player_t;

void talpy_player_init(talpy_player_t *p, const talpy_set_t *set, uint32_t seed, uint32_t now_ms); // TALPY_LOADING, resting
void talpy_player_set_mood(talpy_player_t *p, talpy_mood_t mood, uint32_t now_ms); // same mood: nothing; else rest of the new mood, a new pause, a reaction stops
bool talpy_player_react(talpy_player_t *p, uint32_t now_ms);   // starts finished_clip; false and nothing while mood is TALPY_NEEDS
bool talpy_player_tick(talpy_player_t *p, uint32_t now_ms);    // true if the frame to show changed
uint16_t talpy_player_frame(const talpy_player_t *p);          // index into set->frames
```

Rules: times compare wrap-safe (`(int32_t)(now - due) >= 0`). A tick advances at most one step; a step that ends late starts its successor at `now`, not at the old due time. While resting, the rest clip loops step by step; when `pause_due` passes, the next step is the first step of a clip picked by weight from the mood's picks. A clip's last step ending → resting, new pause drawn uniformly in `[pause_min_ms, pause_max_ms]`. The reaction ending → resting in the current mood.


Notes: per widget, a heap struct (player, `lv_image_dsc_t` with `LV_COLOR_FORMAT_RGB565A8`, stride `w*2`, `data_size = w*h*3`, magic `LV_IMAGE_HEADER_MAGIC`, the buffer from `heap_caps_malloc(..., MALLOC_CAP_INTERNAL | MALLOC_CAP_8BIT)` falling back to `MALLOC_CAP_SPIRAM`), freed on `LV_EVENT_DELETE`. A 20 ms `lv_timer` calls `talpy_player_tick(lv_tick_get())`; when it returns true, decode the frame into the buffer, `lv_image_cache_drop(&dsc)`, `lv_obj_invalidate(img)`. The image is not clickable (taps go through to the screen's double tap). Seed: `esp_random()`. A decode failure leaves the last frame and prints once, always (as the board's other errors do): `printf("talpy: frame %u doesn't decode\n", i)` (C file: stdout is the same UART as `Serial`).
